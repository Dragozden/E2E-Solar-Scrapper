# 11.5e.2 — manual OCR STC approval

The separate `scripts/approve_panel_pdf_ocr.py` command replays the OCR table reconstruction from `job.json`, `document.pdf`, `review.json`, `ocr_evidence_pageN.json`, and `ocr_table_review_pageN.json`. It validates hashes, exact model, power, page, column, original product/PDF URLs, all six STC values and equality of the reconstructed report. The hash chain detects changes to these files relative to each other; it does not authenticate an attacker-controlled replacement of all evidence. Visual confirmation of the original PDF remains mandatory for writes. Preview is read-only; `--approve --confirm-visual` opts in to an append-only insert.

Migration 009 adds `ocr_evidence_sha256` and extends the allowed method values in the existing approval table. The old default method `local_pdf_manual_v1` is preserved. OCR records use `local_pdf_ocr_manual_v1`, the raw OCR evidence hash, and the reconstructed table review hash. Existing unique keys are unchanged; a conflicting method or different evidence for the same PDF/variant is rejected. Existing approved text records and historic price data are not rewritten. Both evidence files and original PDF must be retained outside the repo.

Silver appends the new evidence hash after existing columns; Gold appends `pdf_approval_method`, `pdf_ocr_evidence_sha256` and `pdf_stc_quality`. `technical_source` remains `PDF_APPROVED` for backwards compatibility. For OCR approvals only, any HTML parse issue outside the explicit six `conflicting_*` STC fields keeps `technical_status=REVIEW`, even when `pdf_stc_quality=PASS`. Unknown issues fail closed. No inference of bifaciality, temperature coefficients, warranties or other non-STC values. This pilot intentionally leaves the legacy text-PDF status policy unchanged; it must be reviewed separately. The existing catalog title/power validation is reused; exact PDF URL must still be linked in Gold. The command checks effective Gold provenance after insertion in the same transaction; if the OCR record is not visible or unresolved issues are concealed, the transaction fails.

## Installation

1. Make sure your normal verified DB backup is current. Extract ZIP into the repo root. Do not delete volumes.
2. `uv run --frozen python -m pytest tests/test_panel_pdf_ocr_approval.py -q` (26 tests), then `uv run --frozen python -m pytest -q` (expected 524, assuming unchanged baseline).
3. From repo root run `uv run --frozen python scripts/migrate_panel_pdf_ocr_approvals.py` while no enrichment/dbt job is running. Migration is repeatable; it adds one column and replaces named check constraints in a transaction.
4. From docker directory run `docker compose exec airflow /opt/airflow/solar-venv/bin/dbt build --project-dir /opt/airflow/solar/dbt --profiles-dir /opt/airflow/solar/dbt`. Do not proceed if it fails.
5. From root run `uv run --frozen python scripts/approve_panel_pdf_ocr.py --folder "$folder" --page 2 --confirm-model "JAM60D40-505/LB"`. Inspect PREVIEW_ONLY, exact linked PDF and all STC values. Only after visual inspection and preview, add `--confirm-visual --approve`. A successful approval with unresolved bifaciality is still REVIEW, and the 19 PASS count is expected to remain unchanged if catalog unchanged. Repeat identical write to test idempotence. Run dbt test after an actual OCR row exists, so the new singular test is not vacuous.

No dependency changes. Tested offline on actual submitted OCR evidence + PDF and automated tests, not against live PostgreSQL. Do not change existing text importer to accept OCR JSON.
